# レポートの読み方

## シート（`report.xlsx`）

| シート | 内容 |
|---|---|
| サマリ | 件数、注意事項、この結果の限界 |
| 通達別一覧 | 1 行 = 通達。総合判定と、判定ごとの環境名 |
| 前回との差分 | `--previous` のときだけ。「新たに影響あり」「解消」「継続」「今回の回収なし」 |
| 要更新パッケージ | 1 行 = 環境 × パッケージ。**すべてが直る版**、件数、最も厳しいランクと最も早い期限。**対応はここから始める** |
| 通達×環境 | 行 = 通達、列 = 環境 |
| 明細 | 1 行 = 通達 × 環境 × パッケージ。影響なし・未使用も含む全件（証跡） |
| 新規検出（参考） | 通達に無いが、照合で見つかった脆弱性 |
| 収集状況 | 環境ごとの回収日時、回収ファイル、読めなかったフォルダ、走査範囲外で動くプログラム |

- CSV（BOM 付き UTF-8）も出ます: `report_summary.csv`、`report_detail.csv`、`report_updates.csv`、`report_new_findings.csv`、`report_changes.csv`。
- Excel の 1 シートは先頭 10 万行までです（`config.yaml` の `xlsx_max_rows`）。CSV は常に全件です。

## 判定

| 値 | 意味 |
|---|---|
| 影響あり | 脆弱性データで検出、版が条件に該当、または KB 未適用 |
| 影響あり（比較不能） | 製品はあるが版を比べられない（安全側） |
| 影響なし | 製品はあるが、版が条件の外・修正済み・KB 適用済み |
| 影響なし（CVE未検出） | CVE だけの通達で検出されなかった（未使用と区別できない） |
| 未使用 | 製品が回収物に無い |
| 対象外 | Windows 向けの通達に対する Linux 環境など |
| 判定不能 | 判定に必要なものを回収できていない |

「影響あり」は版の一致です。実際に攻撃できるかは人が判断します。

## 社内ランクと対応期限

通達にランク・日数があればそれを使います。無ければ CVSS v3 と公開区分で決めます（`config.yaml` の `rank_matrix`）。

| CVSS v3 | internet | internal |
|---|---|---|
| 9.0 以上 | Rank-S（3 日） | Rank-A（14 日） |
| 7.0 以上 | Rank-A（14 日） | Rank-B（30 日） |
| 4.0 以上 | Rank-B（30 日） | Rank-C（90 日） |
| 4.0 未満・不明 | Rank-C（90 日） | Rank-C（90 日） |

対応期限 = 公表日（無ければ実行日）+ 日数。過ぎていれば備考に「期限超過」と出ます。

## この結果の限界

「未使用」「影響なし」は**回収できた範囲での結果**です。

- 対象外: コンテナの中身、Lambda の実行環境、AWS マネージドサービス、実行ファイル本体（カーネル、node・python のバイナリ、Go / Rust 製 exe の内部）。
- 取りこぼし: 権限不足や走査範囲外のフォルダ、ネットワークドライブ、表に登録していない商用ソフト。「収集状況」で確かめます。
- 脆弱性データ（OSV.dev、Amazon Linux の公式情報）に無い脆弱性は検出しません。製品名の表記が違うと「未使用」になります。
- 使わない系統: RHEL の追加製品・EUS、Ubuntu の FIPS / Realtime（[DEFECTS.md](https://github.com/hsgwa/cve_chk/blob/main/docs/DEFECTS.md) の 4 章）。
- Amazon Linux は x86_64 の情報を arm64 にも使います。EMR 独自のパッケージは含みません。CVSS は Debian のデータの同じ CVE から引きます。

判定できない範囲と代わりの方法は [ROLLOUT.md](https://github.com/hsgwa/cve_chk/blob/main/docs/ROLLOUT.md) の 7 章、他ツールとの比較と実機での確認は [COMPARISON.md](https://github.com/hsgwa/cve_chk/blob/main/docs/COMPARISON.md) にあります。
